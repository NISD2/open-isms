# Schema-Driven Form Factory

Automatically render shadcn/ui forms from Zod schemas (generated by drizzle-zod), with LLM-powered prefill from unstructured text and files.

## Pipeline

```
Drizzle table       →  drizzle-zod          →  Zod schema         →  SchemaForm       →  shadcn/ui
(schema/tables/*.ts)   (createInsertSchema)    (schema/validators.ts)  (lib/forms)        (auto-rendered)
```

The same Zod schema does triple duty:
1. **Database validation** — drizzle-zod insert/update
2. **Form rendering** — schema-introspect → correct field types
3. **LLM extraction** — Vercel AI SDK generateText with Output.object() → structured data from pasted text/files


## How It Works

### Form Factory

1. `drizzle-zod` generates Zod schemas from Drizzle table definitions (`validators.ts` — already done)
2. `schema-introspect.ts` walks the Zod schema's `.shape`, reads each field's `_def.type` and refinements (Zod v4 API)
3. `field-renderer.tsx` maps each Zod type to a shadcn/ui component
4. `schema-form.tsx` wires it together with `react-hook-form` + `zodResolver`

### LLM Prefill

1. User clicks "KI-Ausfüllung" button on any form
2. Modal opens with a textarea + drag-and-drop zone
3. User either pastes text OR drops a file (PDF, DOCX, TXT, RTF)
4. If file: client-side extraction via `unpdf`/`mammoth` → text appears in textarea
5. User can review/edit the text, then clicks "Daten extrahieren"
6. Text + fields sent via tRPC mutation (`llm.extract`) → Vercel AI SDK `generateObject()`
7. LLM returns structured data matching the Zod schema
8. Hook calls `form.setValue()` for each extracted field
9. Form is prefilled but NOT submitted — user reviews and submits manually

```
                │         LLM Prefill Modal        │
```

## Type → Component Mapping

| Zod Type | Refinement | shadcn Component |
|----------|-----------|-----------------|
| Zod v4 `_def.type` | Refinement | shadcn Component |
|---------------------|-----------|-----------------|
| `string` | (default) | `<Input />` |
| `string` | `.email()` / `.url()` | `<Input type="email" />` / `<Input type="url" />` |
| `string` | `.max(n)` where n > 255 | `<Textarea />` |
| `number` | any | `<Input type="number" />` |
| `boolean` | any | `<Checkbox />` |
| `enum` | any | `<Select />` with `.options` |
| `date` | any | `<Input type="date" />` (or DatePicker) |
| `optional` | wraps inner | unwrap, render inner, mark as optional |
| `nullable` | wraps inner | unwrap, render inner |
| `default` | wraps inner | unwrap, render inner, use default value |
| `array` | of primitives | multi-select or tag input |

## Dependencies

```bash
# Already in your project
bun add zod drizzle-zod

# Frontend (when you add Next.js / React)

pnpm dlx shadcn@latest add form input textarea select checkbox button dialog

# File parsing (client-side)
bun add unpdf mammoth

bun add ai @ai-sdk/anthropic   # or @ai-sdk/openai
```

## Usage

### Basic form from schema

```tsx
import { SchemaForm } from "@/lib/forms";
import { companyInsertSchema } from "@/schema/validators";

<SchemaForm
  schema={companyInsertSchema}
  onSubmit={(data) => createCompany(data)}
/>
```

### With German labels and field overrides

```tsx
<SchemaForm
  schema={companyInsertSchema}
  onSubmit={handleSubmit}
  columns={2}
  fieldOverrides={{
    name: { label: "Firmenname" },
    entityType: { label: "Einrichtungstyp", description: "Gem. §28 BSIG" },
    sector: { label: "Sektor", description: "NIS2-Sektor gem. Anlage 1/2" },
  }}
/>
```

### With LLM prefill

```tsx
import { SchemaForm } from "@/lib/forms";
import { companyInsertSchema } from "@/schema/validators";

// Just set llmPrefill={true} — uses tRPC mutation internally
<SchemaForm
  schema={companyInsertSchema}
  onSubmit={handleSubmit}
  llmPrefill
/>
```

The user can now:
- Paste an email from BSI, a company registration document, an audit report
- Or drag-and-drop a PDF/DOCX policy document
- Click "Daten extrahieren" → form fields auto-populate

## Architecture Decision: Why Not AutoForm?

We build our own (~150 lines) because:

1. **We need i18n labels** — translated via `messages/requirements/{en,de}.json`, not just `humanize(fieldName)`
2. **We need conditional fields** — "show only for KRITIS operators", "skip if entityType === 'important'"
3. **We need form ordering from the DB** — `sortOrder` field on form fields
4. **We need custom field types** — file upload with evidence lifecycle, risk matrix selectors
5. **Zero extra dependencies** — just shadcn + react-hook-form + zod (already required)
6. **Full control** — no fighting someone else's abstraction when requirements get complex

## Architecture Decision: Why Client-Side File Parsing?

- **No server round-trip** for file → text conversion
- **Privacy** — the PDF/DOCX never leaves the browser until the user explicitly sends the extracted text
- **Speed** — unpdf and mammoth are fast, dynamic-imported only when needed
- **Same pattern as rechtsprechung** — proven approach with unpdf + mammoth
