# Lecția 2.2: Ce este un activ?

În 2017, Equifax avea un patch pentru o vulnerabilitate critică. L-au aplicat pe fiecare server, cu o singură excepție. Acel server nu se afla pe nicio listă. O sută patruzeci și șapte de milioane de înregistrări au fost furate prin el. Cauza de bază nu a fost patch-ul lipsă, ci intrarea lipsă din inventar. Această lecție explică ce înseamnă "[[asset|activ]]" în contextul NIS2 și de ce inventarul acelor active este fundația pe care se sprijină orice altă măsură de securitate.

## Ce înseamnă regula

Articolul 21(2)(i) din Directiva NIS2 numește managementul activelor ca fiind una dintre cele zece măsuri de care răspundeți personal. Motivul pentru care se află pe listă este simplu: orice altă măsură, de la patching, control al accesului, criptare, backup (posibil și altele), presupune că cineva are o listă completă a lucrurilor care trebuie protejate. Fără acea listă, măsurile se aplică pe ce își amintește cineva, iar ce uită cineva este exact locul unde se produce incidentul.

Un activ, în limbajul conformității, este orice lucru de care depinde funcționarea afacerii dumneavoastră. Nu doar serverele și laptopurile. Baza de date a clienților, abonamentele cloud, clădirile, furnizorii, angajații care dețin cunoștințe pe care nu le mai are nimeni altcineva și procesele de afaceri care mențin fluxul de venituri. Dacă pierderea unui lucru ar dăuna afacerii, acel lucru este un activ. Lista completă a acestora se numește [[asset inventory|inventarul activelor]], iar ea trebuie ținută la zi. Un inventar care era corect anul trecut și care nu a fost actualizat este deja o lacună.

## De ce vă pasă

Cazul Equifax este cel mai clar exemplu: patch-ul exista, echipa era competentă și procesul era stabilit. Inventarul activelor era incomplet, iar intrarea incompletă este cea care a transformat un ciclu de patching de rutină într-un incident care a costat peste un miliard de dolari. Un auditor nu poate evalua nicio altă măsură fără acest inventar la îndemână, pentru că orice altă măsură este la fel de completă ca lista pe care o acoperă. Lecția 2.14 tratează managementul activelor ca obligație structurată: ce să includeți, cum să clasificați și cum să țineți totul la zi. Această lecție este despre concept: dacă inventarul este greșit, nimic din ce este construit pe baza lui nu este de încredere.

## Ce să întrebați echipa

O singură întrebare: "Arătați-mi inventarul activelor. Când a fost actualizat ultima dată și include abonamentele cloud și accesul contractanților?" Dacă răspunsul acoperă doar serverele și laptopurile, inventarul este incomplet. Dacă data ultimei actualizări este mai veche de șase luni, inventarul se deteriorează.

## Concluzii cheie

1. Un activ este orice lucru de care depinde afacerea: oameni, procese, abonamente cloud și clădiri, nu doar echipamentele IT.
2. Inventarul activelor este fundația pe care se sprijină orice altă măsură de securitate. Dacă lista este incompletă, măsurile construite pe baza ei sunt incomplete.
3. Inventarul vine înaintea tuturor celorlalte lucruri: politicile, matricea de risc și orice altă măsură se construiesc pe baza lui.
