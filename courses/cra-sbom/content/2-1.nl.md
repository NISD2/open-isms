# Les 2.1: CycloneDX: Het op beveiliging gerichte SBOM-formaat

De CRA vereist een "veelgebruikt, machineleesbaar" formaat. Twee formaten komen in aanmerking: [[CycloneDX]] en [[SPDX]]. Deze les behandelt CycloneDX: wat het is, wat het beveiligingsgericht maakt, en waarom het goed aansluit bij de kwetsbaarheidsrapportage-workflow van Artikel 14 van de CRA.

## Wat CycloneDX is

CycloneDX is een OWASP-project. Het Open Web Application Security Project (OWASP) onderhoudt het als standaard voor beveiligingsgerelateerde use cases. De huidige versie is 1.6. Het is beschikbaar in JSON en XML.

CycloneDX is ontworpen voor kwetsbaarheidsbeheer-workflows. Het kern-datamodel is gebouwd rond de vraag: "Gegeven deze lijst met componenten, welke hebben bekende kwetsbaarheden en kan ik daarop handelen?" Elke belangrijke functie in het formaat bestaat om die vraag te beantwoorden.

## Structuur van een CycloneDX SBOM

Een CycloneDX-document bevat vier hoofdsecties:

### Metadata

Informatie over het SBOM-document zelf en het product dat het beschrijft:

```json
"metadata": {
  "timestamp": "2025-03-15T10:30:00Z",
  "tools": [{ "vendor": "Anchore", "name": "Syft", "version": "1.0.0" }],
  "component": {
    "type": "application",
    "name": "MyProduct",
    "version": "2.4.1",
    "purl": "pkg:docker/myproduct@2.4.1"
  }
}
```

De tijdstempel geeft de auditor aan wanneer de SBOM is gegenereerd. De tool geeft aan hoe. Het component-blok identificeert wat de SBOM beschrijft.

### Components

De lijst met softwarecomponenten. Elke component bevat:

- `type`: `library`, `framework`, `application`, `container`, `device`, `firmware`, `file` of `operating-system`
- `name`: de canonieke pakketnaam
- `version`: exacte versietekenreeks
- `supplier`: wie het publiceert
- `purl`: de [[PURL]] unieke identificatie
- `hashes`: SHA-256 of andere hash van het componentbestand
- `licenses`: SPDX-licentie-expressies

```json
{
  "type": "library",
  "name": "requests",
  "version": "2.31.0",
  "supplier": { "name": "Python Software Foundation" },
  "purl": "pkg:pypi/requests@2.31.0",
  "hashes": [{ "alg": "SHA-256", "content": "942c5a758f98..." }],
  "licenses": [{ "expression": "Apache-2.0" }]
}
```

### Dependencies

CycloneDX 1.4+ bevat een `dependencies`-sectie die aangeeft welke component van welke afhankelijk is. Dit is de machineleesbare weergave van de afhankelijkheidsgrafiek. Hiermee kan een tool onderscheid maken tussen componenten op het hoogste niveau en transitieve componenten zonder de buildtool opnieuw uit te voeren.

### Vulnerabilities

CycloneDX kan kwetsbaarheidsgegevens rechtstreeks in de SBOM opnemen. Elke kwetsbaarheidsvermelding verwijst naar een [[CVE]] en het component dat het betreft. Dit is nuttig voor documentatie op een bepaald moment, maar komt in de praktijk minder voor. De meeste teams bewaren de SBOM en de kwetsbaarheidsscan als afzonderlijke artefacten.

## VEX: de functie die CycloneDX onderscheidt

[[VEX]], Vulnerability Exploitability eXchange, is de meest onderscheidende CycloneDX-functie voor CRA-naleving. Een VEX-statement is een machineleesbare verklaring die de relatie tussen een bekende kwetsbaarheid en uw specifieke product documenteert.

CycloneDX VEX ondersteunt vier statuswaarden:

- **not_affected**: het component is aanwezig, maar de kwetsbaarheid kan niet worden misbruikt in dit product
- **affected**: de kwetsbaarheid kan worden misbruikt en u hebt deze nog niet beperkt
- **fixed**: de kwetsbaarheid was aanwezig en u hebt deze verholpen
- **under_investigation**: u beoordeelt de situatie nog

Elke `not_affected`-verklaring vereist een rechtvaardiging:

- `code_not_present`: het kwetsbare codepad bestaat niet in de versie die u gebruikt
- `code_not_reachable`: de kwetsbare code bestaat, maar is niet bereikbaar in uw uitvoeringscontext
- `requires_configuration`: misbruik vereist een configuratie die uw implementatie niet gebruikt
- `requires_environment`: misbruik vereist een omgevingsvoorwaarde die niet van toepassing is
- `protected_by_mitigating_control`: u hebt een compenserende maatregel getroffen
- `protected_at_perimeter`: het getroffen component is niet bereikbaar van buiten uw omgeving

Een VEX-statement `not_affected` met de rechtvaardiging `code_not_reachable`, gedateerd en ondertekend, vormt sterk bewijs in een audit op grond van Artikel 14 dat u de kwetsbaarheid hebt beoordeeld en hebt geconcludeerd dat de rapportageverplichting niet van toepassing was.

## Waarom CycloneDX de voorkeur heeft voor CRA-naleving

De verplichting uit Artikel 14 van de CRA luidt als volgt:

1. Monitor actief misbruikte kwetsbaarheden in de componenten van uw product
2. Als een kwetsbaarheid actief wordt misbruikt, meld dit dan aan de als coördinator aangewezen CSIRT en aan ENISA via het centrale meldplatform: een vroegtijdige waarschuwing binnen 24 uur, een uitgebreidere melding binnen 72 uur en een eindrapport binnen 14 dagen nadat een oplossing beschikbaar is

Het ontwerp van CycloneDX sluit hierbij aan:

- Op PURL gebaseerde componentidentificatie komt rechtstreeks overeen met zoekopdrachten in kwetsbaarheidsdatabases
- VEX-statements bieden een machineleesbare manier om monitoringsbeslissingen te documenteren
- Hulpmiddelen zoals [[Grype]] verwerken CycloneDX SBOMs native en produceren CycloneDX-kwetsbaarheidsscanresultaten
- Het CycloneDX BOM-serienummer (`serialNumber`) maakt het mogelijk om versies van de SBOM in de tijd te volgen

SPDX kan kwetsbaarheidsbeheer uitvoeren, maar is primair ontworpen voor licentiecompliance. CycloneDX is ontworpen voor beveiligingsoperaties. Als uw primaire use case compliance met Artikel 14 is, past CycloneDX beter.

## Een CycloneDX SBOM genereren

[[Syft]] van Anchore produceert standaard CycloneDX 1.6 JSON:

```bash
syft my-container-image:latest -o cyclonedx-json > sbom.cdx.json
```

`cdxgen` is een andere optie, met name voor taal-specifieke builds waarbij een filesystem-scan van Syft toepassingsafhankelijkheden kan missen:

```bash
cdxgen -t java -o sbom.cdx.json .
```

Beide hulpmiddelen produceren geldige CycloneDX 1.6-uitvoer die schema-validatie doorstaat en wordt geaccepteerd door downstream-hulpmiddelen waaronder Grype, Dependency-Track en de meeste kwetsbaarheidsbeheerplatforms.

## Belangrijkste punten

1. CycloneDX is een OWASP-standaard die beschikbaar is in JSON en XML. De huidige versie is 1.6.
2. De vier hoofdsecties zijn: metadata (over de SBOM), components (de inventaris), dependencies (de grafiek) en optioneel vulnerabilities.
3. VEX-statements laten u formeel documenteren of een bekende [[CVE]] exploiteerbaar is in uw specifieke productcontext. Dit is essentieel als bewijs bij een audit op grond van Artikel 14.
4. CycloneDX is het voorkeursformaat voor CRA-naleving omdat het is ontworpen voor kwetsbaarheidsbeheer-workflows, niet voor licentiecompliance.
5. Zowel Syft als cdxgen produceren CycloneDX 1.6-uitvoer. De meeste SBOM-hulpmiddelen richten zich primair op CycloneDX als uitvoerformaat.
