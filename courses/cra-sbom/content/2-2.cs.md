# Lekce 2.2: SPDX a výběr formátu

[[SPDX]] je další formát, který splňuje požadavek CRA Příloha I část II bod (1) na „běžně používaný a strojově čitelný“ SBOM. Tato lekce se zabývá tím, co SPDX je, v čem se liší od CycloneDX a jak rozhodnout, který formát použít.

## Co je SPDX

Software Package Data Exchange (SPDX) vznikl v Linux Foundation v roce 2010. V roce 2021 se stal normou ISO: ISO/IEC 5962:2021. Pro normu ISO je aktuální verze 2.3. Verze 3.0 byla vydána v roce 2024 s novým datovým modelem a systémem profilů.

SPDX byl navržen k řešení problému souladu s licencemi open source. Při dodávce produktu obsahujícího komponenty open source máte právní povinnosti: uvedení autorství, zahrnutí textu licence, zpřístupnění zdrojového kódu u licencí copyleft. SPDX poskytuje strojově čitelný způsob, jak vyjádřit, které licence se vztahují na které komponenty a jaké povinnosti jste přijali.

Postupem času se stal standardem SBOM a nyní pokrývá i pole inventáře komponent potřebná pro správu zranitelností. Původní záměr návrhu (soulad s licencemi) je však v datovém modelu stále patrný.

## Struktura dokumentu SPDX

Dokument SPDX 2.3 ve formátu JSON obsahuje:

- **Informace o vytvoření dokumentu**: ekvivalent metadat CycloneDX: tvůrce, časové razítko vytvoření, jmenný prostor dokumentu, verze SPDX
- **Packages**: inventář komponent. Každý balíček obsahuje: `name`, `version`, `supplier`, `downloadLocation`, `filesAnalyzed`, `packageVerificationCode` nebo `checksums`, `licenseConcluded`, `licenseDeclared`, `copyrightText`, `externalRefs` (sem patří [[PURL]])
- **Relationships**: jak spolu balíčky souvisejí. Vztah `DESCRIBES` označuje produkt nejvyšší úrovně. `DEPENDS_ON` a `DEPENDENCY_OF` mapují graf závislostí.
- **Files** (volitelné): inventář na úrovni souborů s hashi, pokud potřebujete granularitu na úrovni souborů
- **Snippets** (volitelné): úroveň úryvků kódu, pro zkopírovaný kód, který nepochází z balíčku

Pole PURL ve verzi SPDX 2.3 se nachází uvnitř pole `externalRefs`:

```json
"externalRefs": [
  {
    "referenceCategory": "PACKAGE-MANAGER",
    "referenceType": "purl",
    "referenceLocator": "pkg:pypi/requests@2.31.0"
  }
]
```

Tento zápis je podrobnější než prvotřídní pole `purl` v CycloneDX, přesto zůstává strojově čitelný a zpracovatelný nástroji pro skenování zranitelností.

## Výhody SPDX

**Standardizace ISO.** ISO/IEC 5962:2021 znamená, že SPDX je jediným formátem SBOM, který je mezinárodní normou. Pro organizace vyžadující formáty certifikované podle ISO ve svých zadávacích nebo dodavatelských smlouvách to má význam.

**Pracovní postupy souladu s licencemi.** Pokud je vaším hlavním případem použití SBOM soulad s licencemi open source, sledování povinností uvedení autorství, identifikace kódu kontaminovaného GPL nebo generování oznámení třetích stran, je bohatý licenční model SPDX vhodnější. SPDX podporuje identifikátory licencí SPDX, `LicenseInfoInFile` pro detekci licencí na úrovni souborů a `licenseComments` pro složité situace.

**Integrace s grafem závislostí GitHub.** Graf závislostí GitHub nativně exportuje SPDX 2.3 JSON. Pokud je vaše úložiště na GitHubu, poskytuje `github.com/your-org/your-repo/dependency-graph/sbom` SPDX SBOM bez nutnosti spouštět lokální nástroje. Pro mnoho týmů je to nejjednodušší výchozí bod.

**Více výstupních formátů.** SPDX podporuje JSON, YAML, RDF/XML a textový formát tag-value. Formát tag-value je čitelný pro člověka (na rozdíl od JSON nebo XML), což může být užitečné při kontrole.

## Výhody CycloneDX

**Správa zranitelností.** CycloneDX má nativní podporu [[VEX]]. SPDX 3.0 přidala bezpečnostní profil s funkcemi VEX, ekosystémová podpora pro SPDX VEX se však stále vyvíjí. Pro pracovní postupy souladu s článkem 14 je CycloneDX VEX vyspělejší a lépe podporovaný nástroji.

**Dependency-Track.** Přední open-source platforma pro správu SBOM, OWASP Dependency-Track, byla postavena pro CycloneDX. Přijímá vstup SPDX, ale její nativní funkce (porovnávání zranitelností, správa VEX, vyhodnocování zásad) jsou nejúplnější pro CycloneDX.

**Vyspělost nástrojů.** Většina nástrojů SBOM, Syft, cdxgen, trivy, grype, považuje CycloneDX za primární výstupní formát a SPDX za sekundární.

## Oba formáty splňují požadavky CRA na soulad

CRA vyžaduje „běžně používaný, strojově čitelný“. Oba formáty, CycloneDX i SPDX, používají stovky organizací. Oba jsou strojově čitelné. Oba mohou nést pole inventáře komponent požadovaná Přílohou I část II bod (1). Při auditu CRA neuspějete kvůli volbě SPDX místo CycloneDX nebo naopak.

Pokyny Evropské komise i dokument ENISA o osvědčených postupech SBOM odkazují na oba formáty. Žádný oficiální pokyn EU neoznačil jeden formát za upřednostňovaný před druhým.

## Jak vybrat

Použijte toto rozhodovací schéma:

| Otázka | CycloneDX | SPDX |
|---|---|---|
| Primárním případem použití je správa zranitelností a soulad s článkem 14 | ✓ | - |
| Primárním případem použití je soulad s licencemi open source | - | ✓ |
| Používáte Dependency-Track | ✓ | - |
| Vaše zadávací řízení vyžaduje formáty certifikované podle ISO | - | ✓ |
| Vycházíte z exportu grafu závislostí GitHub | - | ✓ |
| Váš tým používá Syft nebo cdxgen | ✓ | - |
| Potřebujete vyspělé nástroje VEX | ✓ | - |

Pokud je primárním zájmem správa zranitelností, zvolte CycloneDX. Pokud již máte pracovní postup SPDX pro soulad s licencemi, je rozšíření o správu zranitelností přijatelné. Mějte však na paměti, že nástroje VEX jsou méně vyspělé.

Mnoho organizací vytváří oba formáty: CycloneDX pro bezpečnostní provoz, SPDX pro právní a zadávací účely. Nástroje to podporují. Syft může z jednoho skenu vygenerovat oba formáty.

## Klíčové poznatky

1. SPDX (ISO/IEC 5962:2021) je formát SBOM standardizovaný ISO. Aktuální verzí pro normu ISO je 2.3, pro nový datový model 3.0. Byl navržen pro soulad s licencemi open source.
2. Oba formáty, [[CycloneDX]] i SPDX, splňují požadavek na „běžně používaný a strojově čitelný“ podle CRA Příloha I část II bod (1). Žádný z nich není oficiálně upřednostňován pokyny EU.
3. Výhody SPDX: status ISO, bohatší licenční model, nativní export grafu závislostí GitHub, více výstupních formátů.
4. Výhody CycloneDX: nativní podpora [[VEX]], integrace s Dependency-Track, vyspělejší ekosystém nástrojů pro správu zranitelností.
5. Pokud je hlavním motorem souladu s CRA článkem 14 hlášení zranitelností, je CycloneDX přirozenější volbou. Vytváření obou formátů z jednoho skenu Syft je platná strategie.
