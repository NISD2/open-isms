# Lekce 2.2: SPDX a volba formátu

[[SPDX]] je druhý formát, který splňuje požadavek článku 13(5) nařízení CRA na "běžně používaný, strojově čitelný" SBOM. Tato lekce vysvětluje, co je SPDX, v čem se liší od CycloneDX a jak se rozhodnout, který formát použít.

## Co je SPDX

Software Package Data Exchange (SPDX) vznikl v roce 2010 v rámci Linux Foundation. V roce 2021 se stal normou ISO: ISO/IEC 5962:2021. Pro normu ISO je aktuální verze 2.3. Verze 3.0 byla vydána v roce 2024 s novým datovým modelem a systémem profilů.

SPDX byl navržen k řešení problému souladu s licencemi open source. Když dodáváte produkt, který obsahuje open source komponenty, máte právní povinnosti: uvedení autorství, přiložení textu licence, zpřístupnění zdrojového kódu u copyleftových licencí. SPDX vám dává strojově čitelný způsob, jak vyjádřit, které licence se vztahují na které komponenty a jaké povinnosti jste přijali.

Časem se z něj stala norma pro SBOM a nyní pokrývá i pole inventáře komponent potřebná pro správu zranitelností. Jeho původní záměr, soulad s licencemi, je ale v datovém modelu stále patrný.

## Struktura dokumentu SPDX

Dokument SPDX 2.3 ve formátu JSON obsahuje:

- **Informace o vytvoření dokumentu** odpovídají metadatům v CycloneDX: tvůrce, časové razítko vytvoření, jmenný prostor dokumentu, verze SPDX
- **Balíčky** představují inventář komponent. Každý balíček má: `name`, `version`, `supplier`, `downloadLocation`, `filesAnalyzed`, `packageVerificationCode` nebo `checksums`, `licenseConcluded`, `licenseDeclared`, `copyrightText`, `externalRefs` (kam patří [[PURL]])
- **Vztahy** popisují, jak balíčky vzájemně souvisejí. Vztah `DESCRIBES` označuje produkt na nejvyšší úrovni. `DEPENDS_ON` a `DEPENDENCY_OF` mapují graf závislostí.
- **Soubory** (volitelné) jsou inventář na úrovni souborů s haši, pokud potřebujete granularitu na úrovni souborů
- **Úryvky** (volitelné) jsou na úrovni úryvků kódu, pro zkopírovaný kód, který nepochází z balíčku

Pole PURL v SPDX 2.3 se nachází uvnitř pole `externalRefs`:

```json
"externalRefs": [
  {
    "referenceCategory": "PACKAGE-MANAGER",
    "referenceType": "purl",
    "referenceLocator": "pkg:pypi/requests@2.31.0"
  }
]
```

Je to upovídanější než prvotřídní pole `purl` v CycloneDX, ale stále je to strojově čitelné a zpracovatelné skenery zranitelností.

## V čem má SPDX výhodu

**Standardizace ISO.** ISO/IEC 5962:2021 znamená, že SPDX je jediný formát SBOM, který je mezinárodní normou. Pro organizace, které ve svých zadávacích řízeních nebo dodavatelských smlouvách vyžadují formáty certifikované podle ISO, na tom záleží.

**Pracovní postupy pro soulad s licencemi.** Pokud je vaším hlavním účelem SBOM soulad s open source licencemi, sledování povinností k uvedení autorství, identifikace kódu kontaminovaného GPL nebo generování upozornění třetích stran, bohatý licenční model SPDX se hodí lépe. SPDX podporuje identifikátory licencí SPDX, pole `LicenseInfoInFile` pro detekci licence na úrovni souboru a pole `licenseComments` pro složité situace.

**Integrace s grafem závislostí na GitHubu.** Graf závislostí na GitHubu nativně exportuje SPDX 2.3 JSON. Pokud máte repozitář na GitHubu, `github.com/your-org/your-repo/dependency-graph/sbom` vám poskytne SBOM ve formátu SPDX, aniž byste museli spouštět jakékoli lokální nástroje. Pro mnoho týmů je to nejjednodušší výchozí bod.

**Více výstupních formátů.** SPDX podporuje JSON, YAML, RDF/XML a textový formát tag-value. Formát tag-value je čitelný pro člověka (na rozdíl od JSON nebo XML), což může být užitečné při revizi.

## V čem má výhodu CycloneDX

**Správa zranitelností.** CycloneDX má nativní podporu [[VEX]]. SPDX 3.0 přidal bezpečnostní profil se schopnostmi VEX, ale podpora SPDX VEX v ekosystému stále dozrává. Pro pracovní postupy souladu s článkem 14 je CycloneDX VEX vyzrálejší a lépe podporovaný nástroji.

**Dependency-Track.** Přední open source platforma pro správu SBOM, OWASP Dependency-Track, byla postavena pro CycloneDX. Přijímá vstup ve formátu SPDX, ale její nativní funkce, párování zranitelností, správa VEX a vyhodnocování zásad, jsou nejúplnější pro CycloneDX.

**Vyzrálost nástrojů.** Většina nástrojů pro SBOM, Syft, cdxgen, trivy, grype, považuje CycloneDX za svůj primární výstupní formát a SPDX za sekundární.

## Oba formáty vyhovují souladu s CRA

CRA vyžaduje "běžně používaný, strojově čitelný" formát. CycloneDX i SPDX používají stovky organizací. Oba jsou strojově čitelné. Oba mohou nést pole inventáře komponent vyžadovaná článkem 13(5). U auditu CRA neuspějete o nic hůř, ať už zvolíte SPDX místo CycloneDX nebo naopak.

Pokyny Evropské komise i dokument ENISA o osvědčených postupech pro SBOM odkazují na oba formáty. Žádné oficiální pokyny EU neoznačily jeden formát za preferovaný před druhým.

## Jak si vybrat

Použijte tento rozhodovací rámec:

| Otázka | CycloneDX | SPDX |
|---|---|---|
| Hlavním účelem je správa zranitelností a soulad s článkem 14 | ✓ | - |
| Hlavním účelem je soulad s open source licencemi | - | ✓ |
| Používáte Dependency-Track | ✓ | - |
| Vaše zadávací řízení vyžaduje formáty certifikované podle ISO | - | ✓ |
| Vycházíte z exportu grafu závislostí na GitHubu | - | ✓ |
| Váš tým používá Syft nebo cdxgen | ✓ | - |
| Potřebujete vyzrálé nástroje pro VEX | ✓ | - |

Pokud je vaším hlavním zájmem správa zranitelností, zvolte CycloneDX. Pokud už máte pracovní postup SPDX pro soulad s licencemi, je rozumné rozšířit jej tak, aby pokrýval i správu zranitelností. Jen mějte na paměti, že nástroje pro VEX jsou méně vyzrálé.

Mnoho organizací vytváří oba: CycloneDX pro bezpečnostní provoz, SPDX pro právní oddělení a nákup. Nástroje to podporují. Syft umí vygenerovat oba ze stejného skenu.

## Klíčové poznatky

1. SPDX (ISO/IEC 5962:2021) je formát SBOM podle normy ISO. Aktuální verze je 2.3 pro normu ISO, 3.0 pro nový datový model. Byl navržen pro soulad s open source licencemi.
2. [[CycloneDX|CycloneDX]] i SPDX se kvalifikují jako "běžně používané, strojově čitelné" formáty podle článku 13(5) nařízení CRA. Žádný z nich není pokyny EU oficiálně preferován.
3. Výhody SPDX: status ISO, bohatší licenční model, nativní export z grafu závislostí na GitHubu, více výstupních formátů.
4. Výhody CycloneDX: nativní podpora [[VEX]], integrace s Dependency-Track, vyzrálejší ekosystém nástrojů pro zranitelnosti.
5. Pokud je vaším hlavním motivem hlášení zranitelností podle článku 14 nařízení CRA, je CycloneDX přirozenější volbou. Vytváření obou formátů z jediného skenu Syft je platná strategie.
