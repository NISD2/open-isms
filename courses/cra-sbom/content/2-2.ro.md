# Lecția 2.2: SPDX și alegerea formatului

[[SPDX]] este celălalt format care îndeplinește cerința din CRA Anexa I, partea II, punctul (1) pentru un SBOM „utilizat în mod curent și lizibil automat”. Această lecție prezintă ce este SPDX, unde diferă de CycloneDX și cum se decide care format se utilizează.

## Ce este SPDX

Software Package Data Exchange (SPDX) a fost creat la Linux Foundation în 2010. A devenit standard ISO în 2021: ISO/IEC 5962:2021. Versiunea 2.3 este actuală pentru standardul ISO. Versiunea 3.0 a fost publicată în 2024 și introduce un nou model de date și un sistem de profiluri.

SPDX a fost conceput pentru a rezolva problema conformității cu licențele open source. Când se livrează un produs care include componente open source, apar obligații legale: atribuire, includerea textului licenței, divulgarea codului sursă pentru licențele copyleft. SPDX oferă o modalitate lizibilă automat de a exprima ce licențe se aplică fiecărei componente și ce obligații au fost asumate.

A devenit ulterior standard pentru SBOM și acoperă acum și câmpurile de inventar al componentelor necesare pentru gestionarea vulnerabilităților. Intenția inițială de proiectare (conformitatea cu licențele) rămâne vizibilă în modelul de date.

## Structura documentului SPDX

Un document SPDX 2.3 JSON conține:

- **Informații de creare a documentului**: echivalent cu metadatele CycloneDX: creator, marcaj temporal de creare, spațiu de nume al documentului, versiune SPDX
- **Pachete**: inventarul componentelor. Fiecare pachet are: `name`, `version`, `supplier`, `downloadLocation`, `filesAnalyzed`, `packageVerificationCode` sau `checksums`, `licenseConcluded`, `licenseDeclared`, `copyrightText`, `externalRefs` (aici se plasează [[PURL]])
- **Relații**: modul în care pachetele se raportează între ele. Relația `DESCRIBES` identifică produsul de nivel superior. `DEPENDS_ON` și `DEPENDENCY_OF` descriu graful de dependențe.
- **Fișiere** (opțional): inventar la nivel de fișier cu hash-uri, dacă este necesară granularitate la nivel de fișier
- **Fragmente** (opțional): nivel de fragment de cod, pentru cod copiat care nu provine dintr-un pachet

Câmpul PURL din SPDX 2.3 se află în matricea `externalRefs`:

```json
"externalRefs": [
  {
    "referenceCategory": "PACKAGE-MANAGER",
    "referenceType": "purl",
    "referenceLocator": "pkg:pypi/requests@2.31.0"
  }
]
```

Acesta este mai detaliat decât câmpul `purl` de prim rang din CycloneDX, dar rămâne lizibil automat și poate fi analizat de scanerele de vulnerabilități.

## Avantajele SPDX

**Standardizare ISO.** ISO/IEC 5962:2021 înseamnă că SPDX este singurul format SBOM care este standard internațional. Pentru organizațiile care solicită în contractele de achiziție sau cu furnizorii formate certificate ISO, acest aspect contează.

**Fluxuri de lucru pentru conformitatea cu licențele.** Dacă utilizarea principală a SBOM este conformitatea cu licențele open source, urmărirea obligațiilor de atribuire, identificarea codului contaminat cu GPL, generarea notificărilor terțe, modelul bogat de licențe din SPDX este mai potrivit. SPDX acceptă identificatori de licență SPDX, `LicenseInfoInFile` pentru detectarea licențelor la nivel de fișier și `licenseComments` pentru situații complexe.

**Integrare cu GitHub dependency graph.** Graficul de dependențe GitHub exportă nativ SPDX 2.3 JSON. Dacă depozitul se află pe GitHub, `github.com/your-org/your-repo/dependency-graph/sbom` oferă un SBOM SPDX fără a rula instrumente locale. Pentru multe echipe acesta este punctul de plecare cel mai simplu.

**Multiple formate de ieșire.** SPDX acceptă JSON, YAML, RDF/XML și un format text tag-value. Formatul tag-value este lizibil de către om (spre deosebire de JSON sau XML), ceea ce poate fi util la revizuire.

## Avantajele CycloneDX

**Gestionarea vulnerabilităților.** CycloneDX are suport nativ [[VEX]]. SPDX 3.0 a adăugat un profil de securitate cu capabilități VEX, dar suportul ecosistemului pentru VEX SPDX este încă în curs de maturizare. Pentru fluxurile de lucru de conformitate cu articolul 14, VEX CycloneDX este mai matur și mai bine susținut de instrumente.

**Dependency-Track.** Platforma principală open source de gestionare a SBOM, OWASP Dependency-Track, a fost construită pentru CycloneDX. Acceptă intrări SPDX, dar funcționalitățile sale native (potrivirea vulnerabilităților, gestionarea VEX, evaluarea politicilor) sunt cele mai complete pentru CycloneDX.

**Maturitatea instrumentelor.** Majoritatea instrumentelor SBOM, Syft, cdxgen, trivy, grype, tratează CycloneDX ca format de ieșire principal și SPDX ca format secundar.

## Ambele formate îndeplinesc cerințele de conformitate CRA

CRA impune „utilizat în mod curent, lizibil automat”. Atât CycloneDX, cât și SPDX sunt utilizate de sute de organizații. Ambele sunt lizibile automat. Ambele pot transporta câmpurile de inventar al componentelor cerute de Anexa I, partea II, punctul (1). O auditare CRA nu va fi eșuată din cauza alegerii SPDX în locul CycloneDX sau invers.

Ghidul Comisiei Europene și documentul ENISA privind bunele practici SBOM fac referire la ambele formate. Niciun ghid oficial UE nu a desemnat un format ca preferat față de celălalt.

## Cum se alege

Se utilizează următorul cadru decizional:

| Întrebare | CycloneDX | SPDX |
|---|---|---|
| Cazul principal de utilizare este gestionarea vulnerabilităților și conformitatea cu articolul 14 | ✓ | - |
| Cazul principal de utilizare este conformitatea cu licențele open source | - | ✓ |
| Se utilizează Dependency-Track | ✓ | - |
| Achiziția impune formate certificate ISO | - | ✓ |
| Se pornește de la exportul dependency graph GitHub | - | ✓ |
| Echipa utilizează Syft sau cdxgen | ✓ | - |
| Este necesar un instrumentar VEX matur | ✓ | - |

Dacă gestionarea vulnerabilităților este preocuparea principală, se alege CycloneDX. Dacă există deja un flux de lucru SPDX pentru conformitatea cu licențele, extinderea acestuia pentru a acoperi gestionarea vulnerabilităților este rezonabilă. Trebuie avut în vedere că instrumentarul VEX este mai puțin matur.

Multe organizații produc ambele formate: CycloneDX pentru operațiuni de securitate, SPDX pentru aspecte juridice și de achiziție. Instrumentele susțin această abordare. Syft poate genera ambele formate din aceeași scanare.

## Concluzii cheie

1. SPDX (ISO/IEC 5962:2021) este formatul SBOM standard ISO. Versiunea actuală este 2.3 pentru standardul ISO și 3.0 pentru noul model de date. A fost conceput pentru conformitatea cu licențele open source.
2. Atât [[CycloneDX]], cât și SPDX se califică ca formate „utilizate în mod curent și lizibile automat” conform CRA Anexa I, partea II, punctul (1). Niciunul nu este preferat oficial de ghidurile UE.
3. Avantajele SPDX: statut ISO, model de licențe mai bogat, export nativ din GitHub dependency graph, multiple formate de ieșire.
4. Avantajele CycloneDX: suport nativ [[VEX]], integrare cu Dependency-Track, ecosistem de instrumente pentru vulnerabilități mai matur.
5. Dacă raportarea vulnerabilităților conform articolului 14 CRA este principalul motor, CycloneDX este alegerea mai naturală. Producerea ambelor formate dintr-o singură scanare Syft reprezintă o strategie validă.
