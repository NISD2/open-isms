# Lekcja 3.1: Budowanie Twojego SBOM-u: narzędzia i integracja z potokiem

Wiedza o tym, co SBOM powinien zawierać, to jedno. Niezawodne generowanie go, jako część procesu budowy, dla każdego wydania, to co innego. Ta lekcja obejmuje narzędzia generujące SBOM-y oraz sposób integracji generowania SBOM-u z potokiem CI/CD, tak aby wynik był zawsze aktualny.

## Dwie kategorie generowania SBOM-u

### Analiza w czasie kompilacji źródła

Narzędzia działające na poziomie źródła odczytują pliki manifestu zależności Twojego kodu, `package-lock.json`, `requirements.txt`, `pom.xml`, `Cargo.lock`, `go.sum`, i generują SBOM z zadeklarowanych zależności. Narzędzia te rozumieją pliki blokady menedżera pakietów i potrafią wygenerować z nich pełne grafy zależności tranzytywnych.

**cdxgen** (CycloneDX Generator) jest najbardziej zaawansowanym narzędziem działającym na poziomie źródła. Obsługuje ponad 30 ekosystemów językowych: Node.js, Python, Java, Go, Rust, .NET, Ruby, PHP i więcej. Odczytuje plik blokady danego ekosystemu i generuje CycloneDX JSON.

```bash
# Node.js project
cdxgen -t npm -o sbom.cdx.json .

# Python project
cdxgen -t python -o sbom.cdx.json .

# Java Maven project
cdxgen -t maven -o sbom.cdx.json .
```

Analiza na poziomie źródła jest dokładna dla zależności aplikacyjnych, ale pomija pakiety systemu operacyjnego i biblioteki systemowe, których nie ma w manifestach specyficznych dla języka.

### Skanowanie obrazu/systemu plików

Skanery obrazów badają zbudowany artefakt, obraz kontenera, katalog systemu plików, skompilowany plik binarny, i identyfikują pakiety z obecnych baz danych pakietów. [[Syft]] od Anchore jest wiodącym narzędziem do tego celu.

```bash
# Scan a container image
syft my-image:1.2.3 -o cyclonedx-json > sbom.cdx.json

# Scan a directory
syft dir:./build -o cyclonedx-json > sbom.cdx.json

# Scan a tarball
syft my-image.tar -o cyclonedx-json > sbom.cdx.json
```

Syft identyfikuje pakiety, odczytując:
- Bazy danych pakietów systemu operacyjnego (dpkg dla Debian/Ubuntu, rpm dla RHEL/Fedora, apk dla Alpine)
- Manifesty pakietów i pliki blokady specyficzne dla języka, osadzone w obrazie
- Sygnatury binarne dla pakietów, które zostały skompilowane i zainstalowane bez menedżera pakietów

Zaleta skanowania obrazu: widzisz dokładnie to, co znajduje się w artefakcie, który zostanie wdrożony. Wada: jeśli pakiet został zainstalowany bez menedżera pakietów (częste w starszych systemach budowy), Syft może go pominąć.

## Najlepsza praktyka: połącz oba podejścia

Uruchom cdxgen na swoim kodzie źródłowym dla zależności aplikacyjnych oraz Syft na swoim obrazie kontenera dla pakietów systemu operacyjnego i środowiska uruchomieniowego. Połącz oba SBOM-y za pomocą narzędzia scalającego. CycloneDX zapewnia operację scalania, która łączy listy komponentów i usuwa duplikaty.

Scalony SBOM obejmuje:
- Zależności aplikacyjne (z cdxgen, pełny graf tranzytywny)
- Pakiety systemu operacyjnego (z Syft)
- Zależności środowiska uruchomieniowego (środowisko Node.js, interpreter Python, JVM)

To jest pełny obraz, którego wymaga CRA i monitorowanie z Artykułu 14.

## Integracja generowania SBOM-u z CI/CD

SBOM powinien być generowany automatycznie jako część Twojego potoku budowy. Ręczne generowanie SBOM-u tworzy ryzyko nieaktualnego lub brakującego SBOM-u, gdy potrzebujesz go do audytu lub reagowania na incydenty.

### Przykład GitHub Actions

```yaml
- name: Generate SBOM
  run: |
    syft my-image:${{ github.sha }} -o cyclonedx-json > sbom-${{ github.sha }}.cdx.json

- name: Upload SBOM as release artifact
  uses: actions/upload-release-asset@v1
  with:
    upload_url: ${{ steps.create_release.outputs.upload_url }}
    asset_path: sbom-${{ github.sha }}.cdx.json
    asset_name: sbom.cdx.json
    asset_content_type: application/json
```

Dołącz SBOM do artefaktu wydania. Każde wydanie otrzymuje SBOM. Nazwa pliku oznaczona SHA tworzy ścieżkę audytu łączącą każdy SBOM z odpowiadającą mu budową.

### Przykład GitLab CI

```yaml
generate-sbom:
  stage: build
  script:
    - syft $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA -o cyclonedx-json > sbom.cdx.json
  artifacts:
    paths:
      - sbom.cdx.json
    expire_in: never
```

`expire_in: never` zapewnia, że GitLab nie usunie artefaktu. W połączeniu z oznaczaniem wydań daje Ci to historię SBOM-ów dla każdego wydania sięgającą tak daleko wstecz, jak potrzebujesz.

## Walidacja Twojego SBOM-u

Przed przechowywaniem lub przesłaniem SBOM-u zwaliduj go:

```bash
# Validate CycloneDX schema
cyclonedx validate --input-format json --input-version v1_6 --input-file sbom.cdx.json
```

CLI CycloneDX jest dostępny z `@cyclonedx/cyclonedx-cli`. Walidacja schematu wychwytuje brakujące wymagane pola, nieprawidłowe typy oraz zniekształcone PURL-e, zanim SBOM trafi do Twojej dokumentacji.

## Podpisywanie Twojego SBOM-u

Podpisany SBOM jest mocniejszym dowodem w audycie niż niepodpisany. Jeśli możesz wykazać, że SBOM został wygenerowany w określonym momencie i nie był od tego czasu modyfikowany, masz mocniejszy łańcuch nadzoru.

Cosign (z projektu Sigstore) może podpisywać i weryfikować pliki SBOM:

```bash
cosign sign-blob --key cosign.key sbom.cdx.json > sbom.cdx.json.sig
```

Plik podpisu dowodzi, że SBOM został wygenerowany przez Twój system budowy i nie został zmieniony. Przechowuj podpis obok SBOM-u.

## Kluczowe wnioski

1. Narzędzia działające na poziomie źródła (cdxgen) odczytują manifesty pakietów i generują pełne grafy zależności tranzytywnych. Skanery obrazów (Syft) badają zbudowane artefakty i znajdują pakiety systemu operacyjnego oraz środowiska uruchomieniowego.
2. Najlepsza praktyka łączy oba: cdxgen dla zależności aplikacyjnych, Syft dla pakietów systemu operacyjnego i środowiska uruchomieniowego, scalone w jeden SBOM.
3. Generowanie SBOM-u musi być zintegrowane z CI/CD. Ręczne generowanie tworzy nieaktualne lub brakujące SBOM-y pod presją.
4. Dołączaj SBOM do każdego artefaktu wydania, oznaczony SHA budowy lub wersją. To tworzy ścieżkę audytu, której wymaga zasada przechowywania przez 10 lat.
5. Waliduj za pomocą CLI CycloneDX przed przechowywaniem. Podpisuj za pomocą Cosign, aby utworzyć łańcuch nadzoru.
