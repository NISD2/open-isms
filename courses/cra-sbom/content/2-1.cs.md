# Lekce 2.1: CycloneDX: Formát SBOM zaměřený na bezpečnost

CRA vyžaduje formát „běžně používaný, strojově čitelný“. Kvalifikují se dva formáty: [[CycloneDX]] a [[SPDX]]. Tato lekce se zabývá CycloneDX: co to je, co ho dělá zaměřeným na bezpečnost a proč se dobře hodí do pracovního postupu hlášení zranitelností podle článku 14.

## Co je CycloneDX

CycloneDX je projekt OWASP. Open Web Application Security Project (OWASP) jej spravuje jako standard pro bezpečnostní případy použití. Aktuální verze je 1.6. Je dostupný ve formátech JSON a XML.

CycloneDX byl navržen pro pracovní postupy správy zranitelností. Jeho základní datový model je postaven na otázce: „Mám-li tento seznam komponent, které z nich mají známé zranitelnosti a mohu na ně reagovat?“ Každá významná funkce formátu slouží k zodpovězení této otázky.

## Struktura CycloneDX SBOM

Dokument CycloneDX obsahuje čtyři hlavní části:

### Metadata

Informace o samotném dokumentu SBOM a o produktu, který popisuje:

```json
"metadata": {
  "timestamp": "2025-03-15T10:30:00Z",
  "tools": [{ "vendor": "Anchore", "name": "Syft", "version": "1.0.0" }],
  "component": {
    "type": "application",
    "name": "MyProduct",
    "version": "2.4.1",
    "purl": "pkg:docker/myproduct@2.4.1"
  }
}
```

Časové razítko auditorovi sděluje, kdy byl SBOM vygenerován. Nástroj mu sděluje, jakým způsobem. Blok component identifikuje, co SBOM popisuje.

### Components

Seznam softwarových komponent. Každá komponenta obsahuje:

- `type`: `library`, `framework`, `application`, `container`, `device`, `firmware`, `file` nebo `operating-system`
- `name`: kanonický název balíčku
- `version`: přesný řetězec verze
- `supplier`: kdo jej vydává
- `purl`: jedinečný identifikátor [[PURL]]
- `hashes`: SHA-256 nebo jiný hash souboru komponenty
- `licenses`: výrazy licencí SPDX

```json
{
  "type": "library",
  "name": "requests",
  "version": "2.31.0",
  "supplier": { "name": "Python Software Foundation" },
  "purl": "pkg:pypi/requests@2.31.0",
  "hashes": [{ "alg": "SHA-256", "content": "942c5a758f98..." }],
  "licenses": [{ "expression": "Apache-2.0" }]
}
```

### Dependencies

CycloneDX 1.4 a novější obsahuje sekci `dependencies`, která mapuje závislosti mezi komponentami. Jedná se o strojově čitelnou reprezentaci grafu závislostí. Umožňuje nástroji odlišit komponenty nejvyšší úrovně od tranzitivních komponent bez nutnosti znovu spouštět nástroj pro sestavení.

### Vulnerabilities

CycloneDX může přímo do SBOM vložit data o zranitelnostech. Každý záznam zranitelnosti odkazuje na [[CVE]] a na dotčenou komponentu. To je užitečné pro dokumentaci v daném okamžiku, v praxi se však používá méně. Většina týmů uchovává SBOM a výstup skenu zranitelností jako samostatné artefakty.

## VEX: funkce, která odlišuje CycloneDX

[[VEX]], Vulnerability Exploitability eXchange, je nejvýraznější funkcí CycloneDX pro soulad s CRA. Výrok VEX je strojově čitelné prohlášení, které dokumentuje vztah mezi známou zranitelností a konkrétním produktem.

CycloneDX VEX podporuje čtyři hodnoty stavu:

- **not_affected**: komponenta je přítomna, ale zranitelnost nelze v tomto produktu zneužít
- **affected**: zranitelnost lze zneužít a dosud nebyla zmírněna
- **fixed**: zranitelnost byla přítomna a byla opravena
- **under_investigation**: hodnocení stále probíhá

Každý výrok `not_affected` vyžaduje odůvodnění:

- `code_not_present`: zranitelná cesta kódu ve používané verzi neexistuje
- `code_not_reachable`: zranitelný kód existuje, ale v daném kontextu spuštění k němu nelze přistoupit
- `requires_configuration`: zneužití vyžaduje konfiguraci, kterou nasazení nepoužívá
- `requires_environment`: zneužití vyžaduje podmínku prostředí, která není splněna
- `protected_by_mitigating_control`: je zavedeno kompenzační opatření
- `protected_at_perimeter`: dotčená komponenta není z vnějšího prostředí dostupná

Výrok VEX typu `not_affected` s odůvodněním `code_not_reachable`, opatřený datem a podpisem, představuje silný důkaz při auditu podle článku 14, že zranitelnost byla posouzena a bylo zjištěno, že nezakládá oznamovací povinnost.

## Proč je CycloneDX pro soulad s CRA upřednostňován

Povinnost podle článku 14 CRA zní:

1. Sledovat aktivně zneužívané zranitelnosti v komponentách produktu
2. Je-li zranitelnost aktivně zneužívána, oznámit ji prostřednictvím jednotné oznamovací platformy určenému CSIRT a ENISA: včasné varování do 24 hodin, podrobnější oznámení do 72 hodin a závěrečnou zprávu do 14 dnů od dostupnosti opravy

Návrh CycloneDX je s touto povinností v souladu:

- Identifikace komponent na základě PURL přímo mapuje na vyhledávání v databázích zranitelností
- Výroky VEX poskytují strojově čitelný způsob dokumentace rozhodnutí o sledování
- Nástroje jako [[Grype]] nativně konzumují SBOM CycloneDX a produkují výsledky skenů zranitelností ve formátu CycloneDX
- Sériové číslo CycloneDX BOM (`serialNumber`) umožňuje sledovat verze SBOM v čase

SPDX zvládne správu zranitelností také, byl však primárně navržen pro dodržování licenčních podmínek. CycloneDX byl navržen pro bezpečnostní provoz. Je-li primárním případem použití soulad s článkem 14, je CycloneDX přirozenější volbou.

## Generování CycloneDX SBOM

[[Syft]] od Anchore ve výchozím nastavení produkuje CycloneDX 1.6 JSON:

```bash
syft my-container-image:latest -o cyclonedx-json > sbom.cdx.json
```

Další možností je `cdxgen`, zejména u jazykově specifických sestavení, kde může souborový sken nástroje Syft přehlédnout závislosti aplikace:

```bash
cdxgen -t java -o sbom.cdx.json .
```

Oba nástroje produkují platný výstup CycloneDX 1.6, který prochází validací schématu a je přijímán navazujícími nástroji včetně Grype, Dependency-Track a většiny platforem pro správu zranitelností.

## Klíčové poznatky

1. CycloneDX je standard OWASP dostupný ve formátech JSON a XML. Aktuální verze je 1.6.
2. Čtyři hlavní sekce jsou: metadata (o SBOM), components (inventář), dependencies (graf) a volitelně vulnerabilities.
3. Výroky VEX umožňují formálně zdokumentovat, zda je známé [[CVE]] zneužitelné v kontextu konkrétního produktu. To je klíčové pro důkazy při auditu podle článku 14.
4. CycloneDX je upřednostňovaný formát pro soulad s CRA, protože byl navržen pro pracovní postupy správy zranitelností, nikoli pro dodržování licenčních podmínek.
5. Syft i cdxgen produkují výstup CycloneDX 1.6. Většina nástrojů pro SBOM cílí na CycloneDX jako primární výstupní formát.
