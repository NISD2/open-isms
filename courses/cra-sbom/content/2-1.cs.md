# Lekce 2.1: CycloneDX: formát SBOM zaměřený na bezpečnost

CRA vyžaduje "běžně používaný, strojově čitelný" formát. Tomuto požadavku vyhovují dva formáty: [[CycloneDX|CycloneDX]] a [[SPDX|SPDX]]. Tato lekce se věnuje formátu CycloneDX. Vysvětlí, co to je, proč je zaměřený na bezpečnost a proč dobře odpovídá pracovnímu postupu hlášení zranitelností podle článku 14 CRA.

## Co je CycloneDX

CycloneDX je projekt OWASP. Open Web Application Security Project (OWASP) jej udržuje jako standard pro bezpečnostní použití. Aktuální verze je 1.6. Je dostupný ve formátech JSON a XML.

CycloneDX byl navržen tak, aby sloužil pracovním postupům správy zranitelností. Jeho základní datový model je postaven kolem otázky: "Které z těchto komponent mají známé zranitelnosti a mohu na ně reagovat?" Každá důležitá funkce formátu existuje proto, aby na tuto otázku odpověděla.

## Struktura SBOM ve formátu CycloneDX

Dokument CycloneDX má čtyři hlavní části:

### Metadata

Informace o samotném dokumentu SBOM a o produktu, který popisuje:

```json
"metadata": {
  "timestamp": "2025-03-15T10:30:00Z",
  "tools": [{ "vendor": "Anchore", "name": "Syft", "version": "1.0.0" }],
  "component": {
    "type": "application",
    "name": "MyProduct",
    "version": "2.4.1",
    "purl": "pkg:docker/myproduct@2.4.1"
  }
}
```

Časová značka říká auditorovi, kdy byl SBOM vygenerován. Nástroj mu říká, jak. Blok component určuje, co SBOM popisuje.

### Komponenty

Seznam softwarových komponent. Každá komponenta má:

- `type`: `library`, `framework`, `application`, `container`, `device`, `firmware`, `file`, nebo `operating-system`
- `name`: kanonický název balíčku
- `version`: přesný řetězec verze
- `supplier`: kdo jej vydává
- `purl`: jedinečný identifikátor [[PURL|PURL]]
- `hashes`: SHA-256 nebo jiný hash souboru komponenty
- `licenses`: licenční výrazy SPDX

```json
{
  "type": "library",
  "name": "requests",
  "version": "2.31.0",
  "supplier": { "name": "Python Software Foundation" },
  "purl": "pkg:pypi/requests@2.31.0",
  "hashes": [{ "alg": "SHA-256", "content": "942c5a758f98..." }],
  "licenses": [{ "expression": "Apache-2.0" }]
}
```

### Závislosti

CycloneDX 1.4+ obsahuje sekci `dependencies`, která mapuje, která komponenta na které závisí. Jde o strojově čitelné vyjádření grafu závislostí. Díky němu může nástroj rozlišit komponenty nejvyšší úrovně od tranzitivních, aniž by musel znovu spouštět build nástroj.

### Zranitelnosti

CycloneDX umí vložit data o zranitelnostech přímo do SBOM. Každý záznam o zranitelnosti odkazuje na [[CVE|CVE]] a na komponentu, které se týká. To je užitečné pro dokumentaci k danému okamžiku, ale v praxi méně obvyklé. Většina týmů udržuje SBOM a výstup skenu zranitelností jako samostatné artefakty.

## VEX: funkce, která CycloneDX odlišuje

[[VEX|VEX]], Vulnerability Exploitability eXchange, je nejvýraznější funkcí CycloneDX pro soulad s CRA. Výrok VEX je strojově čitelné prohlášení, které dokumentuje vztah mezi známou zranitelností a vaším konkrétním produktem.

CycloneDX VEX podporuje čtyři hodnoty stavu:

- **not_affected**: komponenta je přítomna, ale zranitelnost nelze v tomto produktu zneužít
- **affected**: zranitelnost lze zneužít a dosud jste ji nezmírnili
- **fixed**: zranitelnost byla přítomna a vy jste ji opravili
- **under_investigation**: stále provádíte posouzení

Každý výrok `not_affected` vyžaduje odůvodnění:

- `code_not_present`: zranitelná část kódu ve verzi, kterou používáte, neexistuje
- `code_not_reachable`: zranitelný kód existuje, ale ve vašem prováděcím kontextu jej nelze dosáhnout
- `requires_configuration`: zneužití vyžaduje konfiguraci, kterou vaše nasazení nepoužívá
- `requires_environment`: zneužití vyžaduje podmínku prostředí, která neplatí
- `protected_by_mitigating_control`: máte zavedené kompenzační opatření
- `protected_at_perimeter`: postiženou komponentu nelze dosáhnout zvenčí vašeho prostředí

Výrok VEX se stavem `not_affected` a odůvodněním `code_not_reachable`, opatřený datem a podpisem, je při auditu podle článku 14 silným důkazem, že jste zranitelnost posoudili a dospěli k závěru, že nezakládá ohlašovací povinnost.

## Proč je CycloneDX preferován pro soulad s CRA

Povinnost podle článku 14 CRA zní:

1. Sledovat aktivně zneužívané zranitelnosti v komponentách vašeho produktu
2. Nahlásit ENISA prostřednictvím jednotné platformy pro hlášení do 24 hodin, pokud je některá aktivně zneužívána

Návrh CycloneDX tomu odpovídá:

- Identifikace komponent založená na PURL přímo odpovídá vyhledávání v databázích zranitelností
- Výroky VEX vám dávají strojově čitelný způsob, jak dokumentovat rozhodnutí z monitoringu
- Nástroje jako [[Grype|Grype]] nativně zpracovávají SBOM ve formátu CycloneDX a produkují výsledky skenu zranitelností ve formátu CycloneDX
- Sériové číslo BOM v CycloneDX (`serialNumber`) vám umožní sledovat verze SBOM v čase

SPDX umí správu zranitelností zvládnout, ale byl navržen především pro soulad s licencemi. CycloneDX byl navržen pro bezpečnostní provoz. Pokud je vaším hlavním použitím soulad s článkem 14, je CycloneDX přirozenější volbou.

## Generování SBOM ve formátu CycloneDX

[[Syft|Syft]] od Anchore produkuje ve výchozím nastavení CycloneDX 1.6 JSON:

```bash
syft my-container-image:latest -o cyclonedx-json > sbom.cdx.json
```

`cdxgen` je další možností, zejména pro buildy specifické pro daný jazyk, kde sken souborového systému v Syftu může přehlédnout aplikační závislosti:

```bash
cdxgen -t java -o sbom.cdx.json .
```

Oba nástroje produkují platný výstup CycloneDX 1.6, který projde validací schématu a je přijímán navazujícími nástroji, včetně Grype, Dependency-Track a většiny platforem pro správu zranitelností.

## Klíčové poznatky

1. CycloneDX je standard OWASP dostupný ve formátech JSON a XML. Aktuální verze je 1.6.
2. Čtyři hlavní sekce jsou: metadata (o SBOM), komponenty (inventář), závislosti (graf) a volitelně zranitelnosti.
3. Výroky VEX vám umožní formálně zdokumentovat, zda je známá [[CVE|CVE]] zneužitelná ve vašem konkrétním produktovém kontextu. To je pro důkazy k auditu podle článku 14 zásadní.
4. CycloneDX je preferovaný formát pro soulad s CRA, protože byl navržen pro pracovní postupy správy zranitelností, nikoli pro soulad s licencemi.
5. Syft i cdxgen produkují výstup CycloneDX 1.6. Většina nástrojů pro SBOM cílí na CycloneDX jako svůj primární výstupní formát.
